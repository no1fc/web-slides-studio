# Web Slides Studio

**HTML 발표 자료를 업로드하고, 브라우저에서 수정·발표·공유·다운로드하는 개인용 자료실입니다.**

매번 ZIP을 풀고 로컬 파일을 수정하는 대신, 웹 원본과 편집 이력을 한 서버에서 관리합니다. HTML·CSS·JavaScript·이미지·글꼴을 함께 보관하며, 로컬 자산으로 구성한 Three.js 발표 배경도 웹에서 실행할 수 있습니다.

이 저장소에는 애플리케이션 소스와 직접 만든 예제만 포함합니다. 운영 인스턴스 주소, 실제 비밀번호, 개인 발표 자료, 서버 데이터 및 운영 스크린샷은 포함하지 않습니다.

## 일반 사용자 작업 흐름

1. 빈 자료 또는 보고서·강의·제안서 템플릿으로 시작하거나, 여러 ZIP·PPTX를 끌어 놓습니다. 각 파일의 검사·변환 검토·업로드·실패 재시도를 따로 확인합니다.
2. 글을 더블클릭해 수정하고 오른쪽 서식·배치 패널에서 편집합니다. 표·차트 셀 및 링크는 코드 없이 편집합니다. **도구 찾기**(Ctrl/Cmd+Shift+P), **전체 슬라이드**, **서식 패널 접기**로 작은 화면에서도 작업합니다.
3. 디자인에서 템플릿과 브랜드 색·글꼴·로고를 저장합니다. 템플릿은 필요한 자산을 함께 복사한 독립 자료로 만듭니다.
4. 설정 → AI 연결에서 외부 PC용 설치 명령과 프롬프트를 복사합니다. AI 변경은 전후 비교·선택 적용하며 충돌 시 최신 상태에서 다시 요청합니다.
5. 발표 → 발표 전 점검 후 발표자 화면을 엽니다. 청중과 발표자 화면은 이동·검은 화면·레이저를 동기화합니다.
6. 공유는 노트 제외가 기본이며, 만료일과 접근 암호를 설정할 수 있습니다. 파일 → 버전에서 복원·이름 지정을 합니다.

업로드·수정·게시·버전 저장 시각은 구분하며 기본 표시는 Asia/Seoul(KST)입니다. 기존 기록에 없는 시각과 변경 경로는 추정하지 않습니다.

## 빠른 시작 — 로컬 PC

Node.js **22 LTS**와 npm, Chrome 또는 Chromium이 필요합니다. 소스는 Node.js 20 이상을 대상으로 작성했으며 운영 컨테이너는 Node.js 22 기반입니다. Chromium은 PDF/PPTX 출력과 브라우저 테스트에 사용합니다.

```sh
git clone https://github.com/no1fc/web-slides-studio.git
cd web-slides-studio
npm ci --ignore-scripts
npm start
```

관리 화면은 **http://127.0.0.1:4310**, 격리된 발표 콘텐츠는 **http://127.0.0.1:4311**을 사용합니다. 주소의 `127.0.0.1`을 `localhost`로 바꾸면 Host/origin 검사가 달라질 수 있으므로 그대로 접속합니다.

기본 실행은 loopback 전용이며 암호 없이 로컬에서 사용합니다. 외부 공개는 아래 배포 문서를 따라 HTTPS·초기 비밀번호·별도 콘텐츠 origin·렌더러 격리를 구성해야 합니다.

Chrome 경로가 기본값 `/usr/bin/google-chrome`과 다르면 지정하세요.

```sh
# Linux Chromium 예시
CHROME_PATH=/usr/bin/chromium npm start
# macOS Chrome 예시
CHROME_PATH='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' npm start
```

Windows PowerShell에서는 다음과 같이 환경변수를 지정할 수 있습니다.

```powershell
$env:CHROME_PATH = 'C:\Program Files\Google\Chrome\Application\chrome.exe'
npm start
```

현재 개발 검증 환경은 **Windows, Node.js 22.14.0, Chrome 156.0.8078.47**입니다. Linux 운영 환경에서는 설치한 Chromium과 한글 글꼴로 배포 전 검증을 수행하세요. macOS 실행과 실제 PowerPoint 프로그램의 외형 재현은 별도 검증 대상입니다.

기존 서버는 [5단계 Linux 업데이트 안내](docs/STAGE5_LINUX_DEPLOYMENT.md)를 따라 통합 `main`을 재배포합니다. 레이아웃은 기존 HTML과 별도 개체를 보존하며, 새 공유본과 HTML·PPTX 다운로드는 노트를 기본 제외하며, 포함 여부를 선택할 수 있습니다. 기존 공유 링크는 다시 게시하기 전까지 이전 정책을 유지합니다. 6·7단계의 PPTX 가져오기·표·차트·효과도 포함되어 있습니다. 해당 업데이트는 [6·7단계 안내](docs/STAGE6_7_LINUX_DEPLOYMENT.md)를 확인하세요.

**처음 사용한다면:** ‘자료 올리기 → 폴더 선택’에서 [`examples/basic-deck`](examples/basic-deck)을 선택하거나 해당 폴더를 ZIP으로 묶어 올리세요. 별도 외부 자산 없이 두 장의 예제 발표가 생성됩니다.

## Codex·Claude Code에서 직접 수정하기

[AI 제작 안내와 복사용 프롬프트](docs/AI_AUTHORING.md), [설치 가능한 제작 Skill](skills/web-slides-author/SKILL.md)을 제공합니다. 역할별 작업 지침을 공유하는 [agency-agents](https://github.com/msitarzewski/agency-agents)의 사용 방식에서 아이디어를 얻었습니다. 이 저장소의 Skill은 제작·시각 검토·저장 검증 절차를 안내하며, 함께 제공하는 MCP가 실제 서버 API를 호출합니다.

저장소를 내려받은 뒤 다음을 실행하세요. `--client`는 `codex`, `claude`, `all` 중 선택합니다. `all`은 설치된 CLI를 찾습니다.

```sh
npm ci --ignore-scripts
npm ci --prefix integrations/mcp --ignore-scripts
node scripts/install-ai.mjs --client all --url https://slides.example.com --password-file /absolute/private/password.txt --workspace /absolute/deck-workspace
```

- URL은 자신의 서버 주소로 바꿉니다. 비밀번호 파일에는 **현재 로그인 비밀번호**만 한 줄로 저장하고, 저장소 밖에서 본인만 읽을 수 있게 관리하세요. 암호 없는 로컬 서버는 URL과 비밀번호 옵션을 생략할 수 있습니다.
- Skill은 Codex의 `~/.agents/skills/web-slides-author`, Claude Code의 `~/.claude/skills/web-slides-author`에 설치하고, 각 CLI로 사용자 범위 MCP를 등록합니다. 기존 항목 변경은 `--replace`로 명시합니다.
- MCP가 로컬 저장소의 Node 스크립트를 실행하므로 설치 후 이 폴더를 이동하지 마세요. 이동하면 새 경로에서 다시 설치합니다. AI 클라이언트를 재시작하고 해당 도구를 활성화하세요.
- ZIP 가져오기는 지정한 workspace 내부의 일반 ZIP만 허용합니다. 외부 서버는 HTTPS가 필요하며, 비밀번호 값은 MCP 등록 명령에 넣지 않습니다.
- 연결 후 “web-slides-author Skill과 Slides Studio MCP를 사용해서 자료 목록을 확인하고, 선택한 자료를 수정해 줘”라고 요청합니다. 클라이언트의 도구 승인 정책은 그대로 적용됩니다.

MCP는 기존 목록·읽기·생성·수정·저장·ZIP 도구와 함께 실제 연결 진단 및 변경안 제출 도구를 제공합니다. AI 변경안은 파일 → AI 변경 검토에서 전후를 비교하고 선택 적용합니다. 저장할 때 최신 revision을 확인하여 다른 편집을 덮어쓰지 않습니다. 게시·삭제 도구는 제공하지 않습니다. 실제 동작은 인증이 켜진 임시 서버와 표준 MCP 클라이언트로 검증합니다.

발표 버튼을 누르면 현재 장·다음 장·노트·타이머가 있는 발표자 화면이 열립니다. 청중 화면 열기로 두 창을 동기화하거나, 한 화면으로 발표할 수 있습니다. 청중 화면 응답에는 노트가 포함되지 않습니다. 이전/다음 버튼, 방향키·Page Up/Down·Space·Home/End로 이동하고 전체 화면을 선택할 수 있습니다. 발표의 Tab은 링크/버튼 포커스를, 편집 캔버스에서 선택한 개체의 Tab/Shift+Tab은 다음/이전 개체 선택을 지원합니다.

## 무엇이 서버에 저장되나요?

업로드한 **ZIP 파일 자체는 보관하지 않습니다.** 허용한 파일을 압축 해제하고 발표에 필요한 웹 파일과 편집 상태를 저장합니다. HTML에는 편집용 식별자가 추가되므로 최초 업로드 파일과 바이트 단위로 동일한 보관 서비스를 뜻하지 않습니다.

```text
data/
├── _auth.json                  # 암호 salt + scrypt 해시 (인증 사용 시)
└── <자료 UUID>/
    ├── meta.json               # 제목, 폴더, 공유 상태, 파일 정보
    ├── assets/                 # HTML, CSS, JS, 이미지, 글꼴 등
    └── revisions/
        ├── 1.json              # 최초 편집 상태
        └── 2.json              # 다음 저장 상태
```

- ‘파일 관리’에서 자산·이력·메타데이터를 포함한 자료별 사용량을 확인합니다.
- ‘원본 파일 묶음 ZIP’은 보관 중인 웹 파일을 요청 시 압축합니다. 인증정보·공유 토큰·수정 이력 파일은 포함하지 않습니다.
- 수정한 화면이 필요하면 편집기의 ‘다운로드 → 웹 발표 · HTML ZIP’을 사용합니다.
- 원본 파일과 **어느 저장 버전에서든 사용하는 파일**은 개별 삭제를 제한합니다. 이 기능 도입 전 업로드 파일도 안전하게 보호합니다.
- 이 기능 도입 후 추가한 이미지 중 원본·이력에서 참조하지 않는 파일은 확인 후 삭제할 수 있습니다.
- 자료 전체의 서버 파일과 이력은 ‘휴지통 → 완전 삭제’에서 제거합니다. 다운로드 파일을 생성하는 중에는 삭제할 수 없습니다.
- 이미 PC에 내려받은 파일과 외부 백업은 서버 삭제에 영향을 받지 않습니다.
- 출력 작업 결과는 서버 메모리에 잠시 보관하며 30분 후 만료합니다. 완전 삭제 시 해당 자료의 출력 캐시도 무효화됩니다.

## 지원하는 발표 형식

```text
my-deck/
├── index.html
├── style.css
├── app.js
└── assets/
    ├── image.png
    ├── font.woff2
    └── three.min.js
```

- 슬라이드는 `.slide` 요소 또는 같은 부모 아래의 `section` 요소로 인식합니다.
- 고정 **16:9 / 1920×1080** 발표를 우선 지원합니다.
- ZIP 최대 **40 MiB**, 해제 후 **64 MiB**, **300개 파일**, **80장**입니다. 추가 이미지도 해당 자료의 파일 수·자산 용량 제한에 포함됩니다.
- 지원 확장자는 HTML/CSS/JS, PNG/JPG/JPEG/WebP/GIF/SVG/ICO, WOFF/WOFF2/TTF/OTF, JSON, MP4/WebM입니다. 위 확장자는 HTML 패키지 내부 자산입니다. PPTX는 별도 가져오기 버튼으로 지원 요소를 변환합니다(16:9, 40 MiB, 해제 64 MiB, 내부 ZIP 항목 2,000개, 1~80장, 편집 개체 500개). PDF·구형 PPT·PPTM·DOCX·HWP·KEY는 가져오지 않습니다.
- 외부 CDN·API·iframe 의존 자료는 그대로 동작하지 않을 수 있습니다. 라이브러리와 이미지·글꼴을 로컬 경로로 포함하세요.
- 임의 웹사이트나 모든 프레젠테이션 프레임워크를 자동 변환하지 않습니다. 가져온 자료의 레이아웃과 편집 가능한 요소를 먼저 확인하세요.

## 다운로드 형식의 차이

| 형식 | 유지되는 것 | 한계 |
| --- | --- | --- |
| HTML ZIP | 웹 화면·자산·지원 애니메이션·저장한 문자·문단·상자 서식 | 압축 해제 후 사용. 원본이 fetch/ES module을 쓰면 로컬 HTTP 서버가 필요할 수 있음 |
| PDF | 슬라이드 외형, 여백 없는 16:9 | 이미지 기반이므로 글 검색·선택 불가, 애니메이션은 정지 화면 |
| PPTX 외형 보존 | 슬라이드 화면 전체 | 각 장이 한 이미지이므로 개별 문구 편집 불가 |
| PPTX 편집 가능 | 지원 글·이미지·도형·표·차트를 분리하고 문자·문단 서식과 기본 진입 효과를 기록 | 실제로 잘리는 텍스트·표와 CSS 장식·3D는 배경 이미지. 글꼴·줄바꿈 차이 가능 |

텍스트 개체를 선택하면 전체 서식을, 더블클릭하고 글자를 드래그해 선택하면 해당 문자 범위의 서식을 바꿉니다. 자동 맞춤은 저장한 글자 크기·문단 값을 유지하면서 화면 표시를 줄이며 최소 표시 크기는 6px입니다. 여전히 넘치면 상자를 늘리거나 내용을 조정하세요. 이미지·표·다른 편집 개체가 들어 있는 복합 컨테이너는 안쪽 텍스트 개체를 선택해야 합니다. 자세한 조작은 [사용 안내](docs/USER_GUIDE.md#텍스트-전체부분-서식과-문단)를 확인하세요.

Three.js를 PPTX의 네이티브 3D 모델로 변환하는 기능은 없습니다. 편집 가능한 PPTX는 데스크톱 PowerPoint에서의 완전한 재현을 보장하지 않습니다.

open-slide를 참조한 한 줄 상단 바에서 슬라이드·삽입·디자인·파일 메뉴를 엽니다. 글꼴·크기·색·정렬은 오른쪽 **서식**, 위치·크기·그룹은 **배치**, 개체 목록은 **레이어**에서 연속 편집합니다. 상단 **서식** 버튼으로 패널을 접거나 펼칩니다. 코드와 JSON·마스터는 파일 → 고급 도구에 있습니다. 표·차트는 셀을 직접 편집하며, 요소의 **링크**에서 웹 주소나 슬라이드 목록의 이동 대상을 선택합니다. 링크는 발표·공유·HTML과 두 PPTX 형식에서 작동합니다. PDF 링크는 지원하지 않습니다.

자료실의 **PPTX 가져오기**는 16:9 자료의 직접 배치된 텍스트·기본 도형·그림·표·차트·노트를 변환합니다. 변환 경고를 검토한 후 자료를 생성하며, 원본을 무손실로 왕복하는 기능은 아닙니다. 편집기의 **표**, **차트**, **전환·효과** 사용법과 지원 범위는 [6·7단계 안내](docs/STAGE6_7_LINUX_DEPLOYMENT.md)를 확인하세요.

## 로그인과 비밀번호 변경

로컬에서도 인증을 사용하려면 처음 실행할 때 `STUDIO_PASSWORD`를 지정합니다. 명령 이력에 암호를 직접 남기지 않으려면 `.env` 파일에 넣고 Node.js 환경 파일 옵션으로 실행하세요.

```sh
cp .env.example .env
# .env의 STUDIO_PASSWORD를 직접 입력
node --env-file=.env src/server.js
```

상단 **비밀번호 변경**에서 현재 비밀번호, 새 비밀번호, 확인값을 입력합니다. 새 암호는 현재와 다른 12~128자입니다. 저장에는 무작위 salt와 scrypt 해시를 사용하며 새 암호를 평문으로 보관하지 않습니다. 변경 후 현재 창은 새 세션으로 유지하고 다른 세션은 만료합니다.

`STUDIO_PASSWORD`는 **인증 파일이 없는 최초 실행에만** 사용합니다. `_auth.json`이 생긴 뒤에는 환경변수 값을 바꿔도 현재 암호를 덮어쓰지 않습니다. 암호를 잊었을 때의 서버 관리자 복구 절차는 [운영 문서](docs/OPERATIONS.md)를 확인하세요. 암호를 GitHub 이슈나 로그에 붙여 넣지 마세요.

## 개발과 검증

```sh
npm test
npm run test:e2e
npm run test:mcp
```

테스트는 임시 디렉터리에 자체 생성 자료를 사용합니다. 개인 발표 파일이나 실제 운영 계정이 필요하지 않습니다. Chromium 경로를 `CHROME_PATH`로 지정할 수 있습니다.

검증 범위에는 경로 탈출·ZIP/XML 자원 제한·중복 경로, Origin/인증, 저장 충돌, 공유 철회, 출력 일관성, 휴지통 삭제, 파일 보호, 암호 변경·세션 무효화·재시작 후 지속성이 포함됩니다. 코드·마스터·슬라이드·노트·테마, 개체 배치·텍스트·이미지·도형·그룹·표·차트·효과와 PPTX 가져오기를 상태·출력·브라우저 회귀 테스트로 검사합니다. 실제 Windows PowerPoint에서 서비스 출력의 열기·수정·저장·재열기 및 외형 비교도 수행했습니다. 환경과 범위는 [검증 결과](docs/STAGE6_7_VALIDATION.md), 서버 업데이트·수동 검증은 [6·7단계 Linux 적용 안내](docs/STAGE6_7_LINUX_DEPLOYMENT.md)를 참고하세요. 운영 서버의 방화벽·백업과 실제 사용자 자료는 별도로 검증해야 합니다.

### open-slide 참조 개선

REA로 open-slide의 편집·출력 구조를 분석하고 기존 저장·공유 구조에 맞춰 적용했습니다. 세 기본 템플릿의 구성을 개선하고, 비공개 개체/슬라이드 수정 요청을 기존 AI 변경안 비교에 연결했습니다(MCP 0.4.0 이상). PPTX는 웹·내부 링크와 사용 가능한 대체 글꼴을 보존하며 정적 출력의 지연 애니메이션 누락을 줄입니다. [분석 근거와 적용 범위](docs/OPEN_SLIDE_COMPARISON.md), [사용법과 제한](docs/USER_GUIDE.md#도구-찾기와-ai-수정-요청)을 확인하세요.

편집 화면의 실제 참조 실행과 배치 근거는 [UI 비교 기록](docs/OPEN_SLIDE_UI.md)에 정리했습니다. UI용 Geist 글꼴과 Lucide 아이콘은 로컬 제공하며 [라이선스](public/vendor-notices.txt)를 포함합니다.

open-slide의 서식·배치·자산·디자인 패널도 비교하여 빠진 도구를 추가했습니다. [패널별 적용·차이](docs/OPEN_SLIDE_PANELS.md)와 [보관함·디자인 사용법](docs/USER_GUIDE.md#보관함배치전체-디자인)을 확인하세요. 노트를 포함해 게시한 공유본에서는 **발표자 노트 보기**로 내용을 읽을 수 있습니다.
