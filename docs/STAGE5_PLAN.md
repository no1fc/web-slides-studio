# 5단계: 슬라이드 작성 체계

## 목표와 계약

기존 자료를 계속 열 수 있는 상태 모델 위에 슬라이드 구성, 발표자 노트, 구조화된 레이아웃, 공통 테마를 추가한다. 사용자가 5단계 구현·테스트·main 게시를 요청했으며 서버 배포는 사용자가 수행한다.

- 슬라이드 목록: 정적 미리보기, Ctrl/Cmd 다중 선택, Shift 범위 선택, 선택 묶음 드래그 이동, 위/아래 이동·복제·삭제. 순서와 활성 슬라이드는 별개이며 마지막 한 장 삭제는 거부한다. 최대 80장.
- `notes`: 슬라이드 ID → 최대 20,000자 일반 텍스트. 입력 즉시 상태 반영, 자동 저장, 실행 취소, 복제. 가져온 `.notes`는 초기 노트로 보존한다. PPTX 발표자 노트와 HTML 발표 원본에 포함된다(비밀 메모 용도가 아님).
- `slideLayouts`: 슬라이드 ID → `{ type, placeholders }`, type은 `title`, `title-body`, `two-column`, placeholders는 역할(`title`, `body`, `body2`) → 추가 텍스트 개체 ID. 빈 레이아웃은 매핑 제거로 표현한다. 같은 역할 내용은 유지하고, 사라진 역할은 일반 개체로 남긴다. 기존 HTML과 별도 추가 개체는 보존한다.
- 레이아웃 적용은 선택 슬라이드에 자리표시자를 추가/배치한다. 초기화는 자리표시자 위치·기본 서식을 복원하며 텍스트를 보존한다. 삭제하거나 그룹으로 묶은 자리표시자는 해당 매핑에서 분리한다. 리셋은 현재 매핑의 개체에만 적용한다.
- `theme`: `{ colors: { background, text, accent }, fonts: { heading, body } }`. 기본값은 흰 배경·짙은 본문·파란 강조, Arial. 테마 배경은 레이아웃 적용 슬라이드에만 적용한다. 기존 HTML은 자동 재서식하지 않는다.
- 리치 텍스트 run에 선택적 `fontTheme: heading|body`, `colorTheme: text|accent`를 추가한다. 같은 run의 절대 `fontFamily`/`color`와 토큰은 공존하지 않는다. 명시적 글꼴·색 지정은 해당 토큰을 해제한다. 일반 입력·부분 서식·복제·그룹에서 토큰을 유지한다. CSS 변수로 표시하며 내보내기는 실제 계산값을 사용한다.
- 상태 스키마 버전은 1을 유지하고 누락된 필드는 안전한 기본값으로 읽는다. JSON 편집에서도 같은 검증과 제한을 적용한다. 노트·레이아웃·테마는 모든 리비전/복원에 포함한다.
- 정적 썸네일은 원본 사용자 스크립트를 실행하지 않으며 현재 저장 리비전을 표시한다. 선택 이동 시 전체 목록 iframe을 재생성하지 않는다. 3D/애니메이션은 썸네일의 대상이 아니다.

## 구현 순서와 소유 영역

1. 공유 상태/레이아웃 모델: `public/slide-model.js`, `src/deck.js`, 모델 단위 테스트. 레이아웃 API는 불변 `applyLayout(state, slide, type, uid)`, `resetLayout(state, slide)`, `normalizeTheme`, `DEFAULT_THEME`; 검증/렌더 API는 담당자가 정의하고 사용처에 전달한다.
2. 테마 문자 상속: `public/text-model.js`, `public/text-editor.js`, 필요한 `bridge.js`, 문자/브라우저 회귀 테스트. 각 슬라이드에 CSS 변수 `--sd-theme-heading-font`, `--sd-theme-body-font`, `--sd-theme-text`, `--sd-theme-accent`.
3. 서버/출력: `src/server.js`, `src/store.js`, `src/export.js`, 썸네일 렌더 모듈, 해당 테스트. `mode=thumbnail&slide=<ID>`는 정적 1920×1080 문서를 제공한다. UI의 iframe은 고정 원본 크기를 CSS로 축소한다. 저장한 노트는 `.notes`와 PPTX 노트로 출력한다.
4. 편집 화면: `public/app.js`, `authoring-ui.js`, 새 `slide-ui.js`, HTML/CSS. 모델 API를 이용하고 기존 저장·전환 처리에 연결한다.
5. 통합 테스트: 다중 선택/재정렬, 노트 즉시 전환·복제·실행 취소·재접속, 레이아웃 내용 보존·초기화, 테마와 개별 서식, JSON 거부, PPTX/HTML 결과. 브라우저 전체 테스트 동시성은 2로 제한한다.
6. 독립 코드 검토 → 필요한 수정 → 전체 테스트 → 배포/사용 문서 → 테스트한 트리 그대로 GitHub main 게시·해시 검증.

## 판정 기록

- 기존 HTML을 지우지 않고 레이아웃 자리표시자만 관리한다. 원본과 겹칠 수 있으므로 UI에서 알리고 새 빈 슬라이드를 권장한다. 마스터는 기존 별도 공통 배경 레이어를 계속 사용한다.
- 썸네일은 정적 DOM 표시로 구현해 원본 스크립트와 3D 배경을 여러 번 실행하는 비용을 피한다.
- 노트는 발표 자료에 포함되는 콘텐츠다. 공유/다운로드에도 포함됨을 입력 패널에 표시한다.
- 독립 검토에서 기존 20,000자 초과 노트와 크기 한계에 가까운 저장본의 읽기 실패를 재현했다. 원문은 자르지 않고 `sourceNotes`로 보존하며 직접 편집 상태의 제한과 구분한다. 20,000자 초과 원본 노트는 UI에서 읽기 전용이고 공유·출력에는 전체를 유지한다.
- 슬라이드 행 비활성화로 포커스가 빠지는 문제를 실제 클릭 테스트로 수정했다. 삭제한 자리표시자는 숨김 동작과 구분하여 연결을 해제하고 Undo는 역할 연결도 복구한다.
- 순서를 실행 취소할 때 현재 슬라이드가 여전히 존재하면 해당 ID를 유지한다. 1280px에서 도구 모음이 줄바꿈될 때 실제 높이를 반영한다.
- 이전 2,000,000자 최대 크기 상태도 기본값 확장 때문에 실패하지 않도록 정규화 JSON 한도를 2,001,024자로 조정한다. 1,024자는 스키마 확장 호환 여유이며 HTTP 요청 한도는 그대로다. 이전 최대 크기의 저장·재열기와 새 한도 경계를 별도 테스트한다.
