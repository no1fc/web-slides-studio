# 4단계: 이미지·도형·그룹 Linux 업데이트

이 업데이트는 기존 0~3단계 위에 이미지 자르기·Fill/Fit, 도형 편집, 그룹·그룹 해제를 추가합니다. 통합 `main`을 가져와 재배포합니다. 실제 Linux 운영 배포는 관리자가 수행하며 이 문서는 개발 PC 검증과 서버 적용 절차를 구분합니다.

## 포함 범위

- 이미지의 원본 파일을 보존하는 가장자리 자르기, 프레임 채우기(Fill)·맞춤(Fit)·늘이기, 자르기 초기화.
- 사각형·원/타원·선·화살표, 채우기 색/없음, 테두리 색·두께·실선/파선/점선.
- 추가한 텍스트·이미지·도형·그룹의 그룹 생성과 해제. 그룹 이동·회전·비율을 유지한 크기 변경, 복제·복사/붙여넣기·잠금·레이어와 저장/Undo 연동.
- 중첩 그룹은 최대 4단계, 내부 개체를 포함해 500개, 기존 편집 상태 2MB 제한. JSON 편집에서도 같은 검증을 적용합니다.
- HTML ZIP은 같은 이미지·도형·그룹 모델로 재생합니다. 편집형 PPTX는 이미지 원본과 자르기 값, 도형, 지원되는 그룹 자식들을 편집 가능한 개체로 기록합니다.

그룹에 포함할 수 있는 것은 사이트에서 추가한 기본 개체와 그 복제본입니다. 복잡한 원본 HTML/HTML 스냅샷은 그룹 대상이 아닙니다. 단순 원본 이미지는 복제해 독립 이미지로 만든 뒤 자르기 도구를 사용합니다. 장식된 원본 이미지는 HTML 스냅샷으로 유지될 수 있습니다.

PPTX에서 웹 그룹은 개별 편집 가능한 자식으로 풀어 출력하며 PowerPoint 그룹 계층은 생성하지 않습니다. 지원할 수 없는 CSS 장식·클리핑·화면 밖 개체는 배경 이미지에 보존합니다. 그룹 자식 하나라도 지원되지 않으면 그룹 전체를 배경에 보존합니다. PDF와 외형 보존 PPTX는 기존처럼 이미지 기반입니다. 실제 PowerPoint의 픽셀 단위 외형 비교는 6단계 검증 대상입니다.

## 적용 순서

1. 운영 코드를 수정한 내역과 현재 커밋을 확인하고, 쓰기를 중단한 일관된 시점에 코드·환경 파일·`DATA_DIR` 전체를 백업합니다. `_auth.json`, 자산, 모든 revision을 포함합니다.
2. 별도 스테이징 체크아웃과 데이터 복사본에서 아래 작업을 진행합니다. 운영 데이터에 두 프로세스를 동시에 연결하지 않습니다.

```bash
cd /path/to/staging/web-slides-studio
git status --short --branch
git switch main
git pull --ff-only origin main
git rev-parse HEAD
npm ci --ignore-scripts
export CHROME_PATH=/usr/bin/chromium  # 서버의 실제 실행 파일 경로
npm test
git diff --check
```

기존 자체 변경으로 `--ff-only`가 실패하면 별도 브랜치에서 병합합니다. `git reset --hard`로 운영 수정을 지우지 않습니다. Node·Chromium·한글 글꼴과 두 origin 설정은 [3단계 배포 안내](STAGE3_LINUX_DEPLOYMENT.md)의 실행 환경 절차를 그대로 사용합니다. 새 의존성·환경변수·DB 마이그레이션은 없습니다. 추가 스크립트 `object-model.js`도 정적 파일에 포함해야 하므로 전체 소스를 배포합니다.

3. 스테이징에서 아래 수동 검증을 수행합니다.
4. 현재 운영 방식에 따라 새 코드를 배포하고 서비스를 재시작합니다. 저장소의 Compose를 사용한다면 운영 경로·환경·데이터 마운트를 확인한 후 `docker compose up -d --build`를 실행합니다. 별도 서비스명은 환경에 맞춰 사용합니다.
5. 브라우저를 새로고침하고 운영 예제 자료에서 저장·다시 열기·출력을 확인합니다. 열린 이전 버전 편집 창은 새로고침합니다.

## 서버 검증표

| 검사 | 합격 기준 |
| --- | --- |
| 이전 자료 | 0~3단계 자료의 텍스트·코드·마스터·이미지·레이어가 정상 표시되고 저장됨 |
| 이미지 | 원본 가로/세로가 다른 이미지에 Fill/Fit 적용. 좌/우·상/하 비대칭 자르기 후 새로고침해도 같고 초기화로 원본 영역 복원 |
| 범위 검사 | 대향 자르기 합 99% 초과를 거부하며 직전 상태가 유지됨 |
| 도형 | 네 종류 추가, 채우기 없음·색·테두리·파선·점선 편집 후 저장/재열기 |
| 그룹 | 텍스트·이미지·도형 여러 개를 선택해 그룹. 이동·회전·확대 후 해제해 위치·크기·텍스트/테두리 비율 유지 |
| 레이어 | 다른 개체와 겹친 그룹을 앞/뒤로 이동한 후 해제해 외부 개체와의 순서 유지 |
| 이력 | 그룹/해제가 Undo 한 번으로 복구되고 Redo·자료/슬라이드 복제·버전 복원이 동작 |
| 선택·잠금 | 그룹 내부 클릭 시 그룹 하나 선택. 잠금 상태에서 크기·내용·그룹 해제 불가 |
| 중첩 | 그룹을 다시 그룹화한 뒤 확대·회전·순차 해제. 한도 초과는 전체 명령 거부 |
| HTML | 내려받은 ZIP에서 이미지 Fit·자르기·그룹 변환 및 텍스트 목록 간격 유지 |
| 편집형 PPTX | PowerPoint에서 기본 이미지의 자르기 영역을 다시 조정하고 도형 색·테두리를 바꿀 수 있음. 그룹 자식은 독립 개체로 선택 가능 |
| 파일 보호 | 그룹 안에서 참조하는 이미지가 미사용 파일로 삭제되지 않음 |

너무 크게/작게 조절한 그룹은 해제 후 글자 크기(6~400px), 테두리(0~40px) 또는 위치/크기 제한을 벗어날 수 있습니다. 이 경우 그룹 해제를 전체 거부하고 상태를 유지합니다. 그룹 크기를 조정한 후 다시 시도합니다.

## 롤백

과거 revision 파일을 덮어쓰는 마이그레이션은 없습니다. 다만 이전 프로그램은 새 `image`·`shape`·`group`·`textMetricsScale` 항목을 이해하지 못합니다. 운영에서 4단계로 저장한 후 코드를 되돌릴 경우, 서비스를 중지하고 백업한 코드·환경·`DATA_DIR`를 함께 복원합니다. 새 저장 데이터를 이전 프로그램으로 열어 다시 저장하지 않습니다. 장애 자료는 복사해 보존하고 복원 검증을 별도 경로에서 수행합니다.

## 검증 기록

개발 PC: Windows, Node.js 22.14.0, Chrome 156.0.8078.47. 2026-10-21 최종 `npm test`는 **181/181 통과**, 실패·취소·건너뜀 0, 종료 코드 0이었습니다(약 101초, 테스트 파일 동시 실행 2개). 자동 테스트는 합성 자료로 모델·UI·브라우저·PPTX XML과 기존 회귀를 확인합니다.

실제 부모/iframe 통합 테스트에서 그룹 1.5배 확대·35도 회전 후 저장·새로고침·해제·Undo/Redo를 검사했고 자식 개체 및 글머리표/텍스트 경계 차이는 1px 미만이었습니다. 1600px/1280px 화면 확인에서 브라우저 런타임 오류가 없었습니다. 독립 검토에서 발견한 이미지 원본 누락, 레이어 기본값·겹침, 구버전 도형 텍스트 보존 문제는 재현 테스트와 함께 수정하고 재검토했습니다.

Linux 배포와 실제 PowerPoint 수동 검증은 위 표에 서버 결과를 별도로 기록합니다.
