# 5단계: 슬라이드 구성·노트·레이아웃·테마 업데이트

기존 0~4단계 위에 발표 자료의 구성과 공통 디자인을 관리하는 기능을 추가합니다. 통합 `main`을 가져와 재배포하면 됩니다. 실제 Linux 서비스 배포와 PowerPoint 프로그램의 수동 검증은 운영자가 수행합니다.

## 추가 기능

- 정적 슬라이드 미리보기, Ctrl/Cmd 다중 선택, Shift 범위 선택, 선택 묶음 드래그·위/아래 이동·복제·삭제. 복제본은 선택한 마지막 장 뒤에 원래 순서대로 삽입합니다.
- 발표자 노트 입력·자동 저장·복제·실행 취소·재접속 복원. 기존 HTML의 `.notes`도 읽습니다. 노트는 공유·HTML·PPTX에도 포함됩니다.
- 표지, 제목과 본문, 제목과 두 단 본문 레이아웃. 기존 내용과 다른 개체를 유지하며 제목·본문 자리표시자를 생성합니다.
- 레이아웃 초기화: 현재 연결된 자리표시자의 위치·기본 서식을 복원하고 텍스트를 유지합니다. 레이아웃을 바꾸어 사용하지 않게 된 자리표시자는 일반 개체로 남습니다.
- 배경·본문·강조색과 제목·본문 글꼴 테마. 레이아웃 배경과 테마에 연결된 문자에 적용하고 사용자가 별도로 지정한 글꼴·색은 유지합니다.
- 모든 변경을 JSON 편집, 저장 버전, Undo/Redo와 연결합니다. 복제한 슬라이드의 자리표시자 ID도 독립적으로 바뀝니다.

## 적용 순서

1. 현재 코드 변경과 커밋을 확인하고 코드·환경 파일·`DATA_DIR` 전체를 일관된 시점에 백업합니다. 자산, `_auth.json`, 모든 revision을 포함합니다.
2. 별도 스테이징 경로와 데이터 복사본에서 `main`을 갱신하고 테스트합니다. 운영 데이터를 두 프로세스가 동시에 사용하지 않도록 합니다.

```bash
cd /path/to/staging/web-slides-studio
git status --short --branch
git switch main
git pull --ff-only origin main
git rev-parse HEAD
npm ci --ignore-scripts
export CHROME_PATH=/usr/bin/chromium  # 실제 설치 경로로 지정
npm test
git diff --check
```

`--ff-only`가 실패하면 운영 변경을 별도 브랜치에서 병합합니다. 새 의존성·환경변수·DB 마이그레이션은 없습니다. `public/slide-model.js`, `public/slide-ui.js`, `src/thumbnail.js`를 포함한 전체 소스를 배포합니다. 기존 자료는 읽을 때 기본 필드를 보완하며 과거 revision 파일을 덮어쓰지 않습니다.

3. 아래 검증표를 확인한 뒤 기존 운영 방식으로 재배포합니다. 저장소 Compose를 쓴다면 환경과 데이터 마운트를 확인하고 `docker compose up -d --build`로 다시 빌드·실행합니다.
4. 기존 편집 창을 새로고침하고 저장·재열기·발표·출력을 확인합니다. Node/Chromium/한글 글꼴/HTTPS 두 origin 설정은 [기존 운영 안내](OPERATIONS.md)를 따릅니다.

## 서버 검증표

| 검사 | 합격 기준 |
| --- | --- |
| 기존 자료 | 코드·마스터·텍스트·도형·그룹·이미지를 그대로 열고 저장 가능 |
| 목록 | Ctrl/Cmd로 떨어진 장, Shift로 범위를 선택. 선택 장의 상대 순서를 유지하면서 드래그·위/아래 이동 |
| 복제·삭제 | 선택 장의 노트·레이아웃·개체·코드·마스터 연결 복사. 삭제 후 Undo 한 번으로 복원. 모든 장 삭제와 80장 초과는 상태 변경 없이 거부 |
| 노트 | 노트를 입력하자마자 다음 장으로 이동해도 원래 장에 저장. 비운 노트가 다시 원본으로 돌아오지 않음. 재접속·Undo/Redo·버전 복원 검사 |
| 레이아웃 | 빈 장에 제목/본문 적용. 내용 수정·위치 이동 후 초기화하면 내용은 유지하고 위치·기본 서식 복원 |
| 레이아웃 전환 | 두 단에서 한 단으로 변경 시 두 번째 본문이 일반 개체로 남음. 연결 해제 시 개체 내용 유지 |
| 그룹 | 자리표시자를 그룹으로 묶으면 해당 레이아웃 역할 연결이 해제되고 그룹 내용 유지. 그룹 해제 후 일반 개체로 편집 가능 |
| 테마 | 밝은/어두운 테마 전환과 제목·본문 글꼴 변경. 개별 색·글꼴을 지정한 문자는 유지하고 테마 연결 문자는 변경 |
| 저장/JSON | 새 세 필드와 문자 테마 토큰을 JSON으로 편집·저장 가능. 잘못된 ID·색·글꼴·역할 연결은 거부하고 초안 유지 |
| 썸네일 | 현재 저장 버전의 선택 슬라이드가 보이고 원본 스크립트·3D 배경을 반복 실행하지 않음 |
| HTML | 다운로드·공유에 노트와 테마가 반영되고 원본 발표 기능 유지 |
| PPTX | 두 출력 모드에서 슬라이드 순서와 발표자 노트 확인. 편집형은 표시된 글꼴·색으로 출력. 테마 글꼴이 서버와 PC에 설치되어 있는지 확인 |

## 범위와 롤백

레이아웃은 기존 HTML을 자동으로 재해석하지 않습니다. 가져온 자료에 적용하면 기존 개체와 겹칠 수 있으므로 빈 슬라이드에서 새로 구성하거나 HTML/CSS에서 원본 배치를 조정합니다. 마스터는 기존 공통 배경 레이어 기능을 계속 사용하며 테마와 레이아웃은 웹 편집기의 구조입니다. PowerPoint의 네이티브 슬라이드 마스터/레이아웃 계층으로 변환하는 기능은 포함하지 않습니다.

썸네일은 정적 HTML/CSS·이미지·기본 개체를 표시합니다. 자바스크립트로 생성되는 내용과 3D·애니메이션은 실행하지 않아 발표 화면과 차이가 날 수 있습니다. 직접 편집하는 노트는 장당 20,000자, 전체 편집 상태는 2MB, 슬라이드는 80장, 추가 개체는 그룹 내부를 포함하여 500개 제한입니다. 원본의 기존 장문 노트는 자르지 않고 읽기 전용으로 보존하며 공유·출력에도 전체를 유지합니다.

이전 프로그램은 `notes`, `slideLayouts`, `theme`, `fontTheme`, `colorTheme`를 이해하지 못합니다. 5단계로 저장한 뒤 코드를 되돌릴 때는 서비스를 중지하고 백업한 코드·환경·데이터를 함께 복원합니다. 새 데이터를 이전 프로그램으로 열어 다시 저장하지 않습니다.

기존 2MB 한계에 가까운 자료도 기본 테마 필드 추가로 열리지 않는 일이 없도록 저장 상태 제한에 1,024자 호환 여유를 둡니다. 정확한 한도는 정규화한 JSON 문자열 2,001,024자이며 HTTP 요청 크기 제한은 기존과 같습니다.

## 검증 기록

2026-10-21 개발 PC(Windows, Node.js 22.14.0, Chrome 156.0.8078.47)에서 최종 `npm test` **216/216 통과**, 실패·취소·건너뜀 0, 종료 코드 0이었습니다. 테스트 파일 동시성은 2, 소요 시간은 약 115초입니다. `git diff --check`도 통과했습니다.

실제 Chrome에서 다중 선택·드래그·단축키·복제·삭제, 노트 즉시 전환·실행 취소·재열기, 레이아웃 초기화·개별 서식·삭제된 자리표시자 재생성, 장문 노트의 읽기 전용 보존을 검사했습니다. HTML/PPTX 노트·테마와 원본 스크립트를 실행하지 않는 썸네일을 검증했습니다. 이전 최대 크기 상태의 읽기·저장·재열기와 새 크기 한도의 초과 거부도 확인했습니다.

1600px/1280px 화면에서 런타임 오류 없이 편집 화면을 확인했습니다. 독립 검토의 노트 호환성·포커스·자리표시자 삭제·크기 경계 지적은 회귀 테스트와 함께 수정하고 재검토했습니다. Linux 운영 결과와 실제 PowerPoint 외형 비교는 위 표에 별도로 기록합니다.

## 남은 로드맵

5단계 이후 번호 기준으로 **2단계**가 남습니다.

- **6단계:** 실제 PowerPoint에서 편집성·외형 비교, 글꼴·레이어·회전 호환성 보정과 지원 범위 정리.
- **7단계:** 제한된 PPTX 가져오기 → 표 → 데이터 차트 → 전환·애니메이션 확장. 여러 기능을 포함하므로 작업량이 작은 단일 단계라는 뜻은 아닙니다.
