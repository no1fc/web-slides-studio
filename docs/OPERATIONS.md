# 설치·운영 안내

이 문서의 도메인은 설명용 예시입니다. 실제 운영 인스턴스 주소나 인증정보는 저장소에 포함하지 않습니다.

## 실행 환경

- Node.js 22 LTS 권장, npm 잠금 파일 사용.
- Chrome/Chromium: 브라우저 테스트 및 PDF/PPTX 렌더링에 필요.
- 한글 출력에는 한글 글꼴 필요. Docker 이미지는 Noto CJK를 설치합니다.
- 파일 저장소를 공유하는 여러 Node 프로세스나 replica는 지원하지 않습니다.

## 환경변수

| 변수 | 기본값 | 용도 |
| --- | --- | --- |
| `HOST` | `127.0.0.1` | 서버 바인딩. 외부 바인딩은 HTTPS origin·암호 필수 |
| `PORT` | `4310` | 관리 HTTP 서버 포트 |
| `CONTENT_PORT` | `4311` | 발표 콘텐츠 HTTP 서버 포트 |
| `DATA_DIR` | 프로젝트의 `data/` | 자산·revision·인증 파일 저장 |
| `STUDIO_PASSWORD` | 없음 | `_auth.json`이 없을 때 최초 암호 |
| `APP_ORIGIN` | 로컬 관리 주소 | 브라우저가 접속할 관리 origin |
| `CONTENT_ORIGIN` | 로컬 콘텐츠 주소 | 관리와 다른 발표 콘텐츠 origin |
| `CHROME_PATH` | `/usr/bin/google-chrome` | 출력·테스트용 실행 파일 경로 |

예제 `.env`를 복사하고 본인 값으로 편집하세요. 앱이 `.env`를 자동으로 읽지는 않습니다. 로컬 Node 실행에는 `node --env-file=.env src/server.js`를 사용합니다. Docker Compose는 `.env` 값을 치환합니다.

암호가 해시 파일에 저장된 뒤에는 환경변수의 초기값을 변경해도 현재 암호가 바뀌지 않습니다. 이후 변경은 관리 화면에서 수행하세요. 초기 암호를 더 이상 환경 파일에 유지하지 않으려면 인증 파일이 정상 보존되는지 확인한 뒤 운영 구성을 수정할 수 있습니다.

## Docker 빌드

```sh
docker build -t web-slides-studio:local .
```

이미지에는 `src`, `public`, 패키지 명세만 복사합니다. `data`, `.env`, 테스트 산출물, 내부 문서는 포함하지 않습니다. 애플리케이션은 UID 1000의 node 사용자로 실행합니다.

`compose.example.yml`은 HTTPS reverse proxy 뒤에서 사용하는 예시입니다. 두 내부 포트를 호스트의 loopback에만 바인딩하고 내부 전용 Docker 네트워크, 읽기 전용 root, 제한된 임시 영역, 메모리·CPU·PID 제한을 적용합니다.

```sh
cp .env.example .env
# .env에 초기 암호와 실제 두 HTTPS origin 입력
mkdir -p data
# data는 컨테이너 UID 1000이 쓸 수 있어야 합니다.
docker compose -f compose.example.yml up -d --build
```

호스트 사용자의 UID가 다르면 해당 data 디렉터리에 한해 소유권/권한을 맞추거나 이름 있는 볼륨을 적절히 초기화하세요. 시스템 전체의 소유권이나 권한을 바꾸지 마세요. 파일 권한 오류가 발생하면 앱 로그와 마운트 경로부터 확인합니다.

## HTTPS와 콘텐츠 격리

예를 들어 관리 화면을 `https://slides.example.com`, 발표 콘텐츠를 `https://content.example.com`에 연결합니다. 두 도메인의 DNS·TLS 인증서를 직접 준비해야 합니다.

1. 관리 도메인은 내부 4310, 콘텐츠 도메인은 내부 4311로 reverse proxy합니다.
2. 원래 `Host` 헤더를 유지합니다. 앱은 설정한 origin의 Host만 허용합니다.
3. 관리 쿠키는 콘텐츠 origin에 공유하지 않습니다.
4. 관리 요청 본문 크기 제한을 최소 40 MiB, 출력 요청 시간 제한을 용도에 맞게 설정합니다.
5. 업로드 스크립트는 콘텐츠 iframe에서 실행되므로 관리 origin과 같게 설정하지 마세요.
6. 렌더러 컨테이너의 외부 통신과 호스트 내부 자원 접근을 제한합니다. CSP와 Playwright 요청 차단만으로 OS 격리를 대신하지 마세요.

호스트 nginx용 예시는 [`ops/nginx.example.conf`](../ops/nginx.example.conf)에 있습니다. 실제 인증서 경로·도메인으로 바꾸고 `nginx -t` 후 reload합니다. nginx가 별도 컨테이너에 있다면 loopback 대신 공유 내부 네트워크의 서비스 이름으로 연결해야 합니다. 기존 컨테이너나 DB를 내릴 필요는 없습니다.

콘텐츠 미리보기 URL은 임의 토큰을 포함합니다. 관리 API가 인증된 사용자에게만 발급하지만, URL 자체를 전달하면 열람 권한도 전달됩니다. 로그·공개 이슈에 붙여 넣지 마세요.

## 비밀번호와 세션

- 최초 암호는 `_auth.json`에 무작위 salt와 scrypt 해시로 저장합니다. 파일 권한은 600입니다.
- 현재 암호 재확인 후에만 새 암호를 저장합니다. 새 암호는 12~128자이며 기존 암호와 달라야 합니다.
- 변경은 직렬 처리하며 성공한 변경은 이전 세션을 모두 만료시킵니다. 변경 요청의 현재 창에는 새 세션을 발급합니다.
- 세션은 프로세스 메모리에 저장합니다. 재시작하면 다시 로그인해야 합니다.
- 암호 파일이 손상되면 시작에 실패하며 초기 암호로 조용히 돌아가지 않습니다.
- 로그인과 암호 재확인은 요청 횟수 제한을 적용합니다. reverse proxy 환경의 IP 집계 방식은 실제 토폴로지에 맞춰 추가 검토하세요.

### 암호를 잊었을 때

서버 파일에 접근할 수 있는 관리자만 복구합니다.

1. 앱 프로세스만 중지합니다.
2. data 전체를 비공개 위치에 백업합니다. `_auth.json`은 민감한 인증 파일입니다.
3. 기존 `_auth.json`을 백업 위치로 옮깁니다. 발표 자료 폴더는 그대로 둡니다.
4. 새로운 초기 `STUDIO_PASSWORD`를 비공개 환경 파일에 설정하고 앱을 시작합니다.
5. 새 암호로 로그인하고 인증 파일 생성·발표 자료 보존을 확인합니다.

다른 사람이 앱에 접속 중인 상태에서 인증 파일을 제거하지 마세요. 원격 운영에 암호 없는 기본값을 사용하지 마세요.

## 백업과 복원

자동 백업 스케줄은 제공하지 않습니다. 외부 스케줄러·백업 도구로 data 전체를 보존하세요. 수정 이력 자체가 장비 고장에 대비한 백업은 아닙니다.

일관된 백업의 가장 간단한 방법은 앱만 잠깐 멈춘 상태에서 data 전체를 복사하고 즉시 다시 시작하는 것입니다. 원본 자산, meta, 모든 revision, 인증 파일을 함께 복사합니다. 데이터가 없는 소스 저장소만으로는 사용자 발표를 복구할 수 없습니다.

복원은 별도 경로·테스트 인스턴스에서 먼저 확인하세요. 개인 자료를 공개 테스트 서버로 복원하지 않습니다. 사용하던 암호 파일까지 복원했다면 그 시점의 암호가 유효해집니다.

## 업데이트와 롤백

새 소스에서 `npm ci --ignore-scripts`, `npm test`를 실행하고 새 이미지 태그로 빌드합니다. 컨테이너를 교체할 때 동일한 data 마운트를 사용합니다. 기존 이미지를 보관하면 코드 롤백이 가능합니다.

비밀번호 변경 기능 도입 이전 코드로 돌아가면 `_auth.json`을 읽지 못하고 환경변수의 초기 암호를 다시 사용할 수 있습니다. 따라서 인증 기능 이전 버전으로의 롤백은 정상적인 암호 유지 방법이 아니며 별도 인증 점검이 필요합니다.

## 상태 확인과 제한

- 관리 서버 `/health`는 정상 동작 시 200 JSON을 반환합니다. Host 헤더는 관리 origin에 맞춰야 합니다.
- 출력은 한 번에 하나입니다. 작업 중 추가 요청은 429이며 결과는 30분 후 만료합니다.
- 출력 중 자료나 파일의 완전 삭제는 거부합니다.
- Chromium 출력은 큰 메모리를 사용합니다. 동시 요청, 원본 복잡도, 3D 장면에 따라 메모리·시간 제한을 조정해야 할 수 있습니다.
- 저장 이력은 계속 쌓입니다. 디스크 여유 공간·컨테이너 로그·백업 성공 여부를 별도로 관찰하세요.
- 데이터와 인증정보는 버전 관리·공개 이미지·정적 파일 경로에 넣지 않습니다.
