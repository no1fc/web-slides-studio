# 2단계: 0·1·2단계 통합 Linux 업데이트

이 업데이트는 코드·마스터 편집(0단계), 정밀 조작·배율(1단계), 다중 선택·개체 배치·레이어(2단계)를 함께 포함합니다. 기준 공개본은 `029e4443b551e244db98f123c5d376d142fb3aea`입니다. GitHub `main`의 통합 소스를 기준으로 업데이트하며, 실제 운영 서버 반영은 관리자가 수행합니다.

이 문서는 배포 절차입니다. 실제 Linux 운영 서버에 접속하거나 배포·검증을 완료했다는 의미는 아닙니다. 이전 단계의 패치 파일을 통합 `main`에 중복 적용하지 마세요.

## 포함 기능과 지원 범위

- HTML/CSS·JSON 편집, 기본 구성 생성, 공통 마스터 작성·연결, 저장 실패 초안 복구.
- 개체 크기·회전 핸들, 비율 유지·중심 조절, 방향키 이동, 화면 맞춤·25~200% 배율.
- 수정키 클릭·영역 선택·전체 선택, 다중 이동·숨기기와 한 번의 Undo, 드래그 전체 취소.
- 독립 복제와 같은 자료의 슬라이드 간 앱 내부 복사·붙여넣기. 운영체제 클립보드는 사용하지 않습니다.
- 선택한 전체 범위 기준 정렬, 양 끝을 고정한 가로·세로 간격 분배.
- 레이어 목록에서 가려진 개체 선택, 숨김·표시, 잠금·해제, 앞뒤 순서 변경.

레이어 순서는 HTML의 같은 부모 요소 안에서 적용하며 서로 다른 컨테이너의 CSS 겹침 범위를 합치지 않습니다. 잠금은 편집기 조작 보호 기능이며 권한 기능이 아닙니다. JSON·코드 편집으로 명시적으로 변경할 수 있습니다.

복제는 기본 글·이미지·도형과 지원되는 HTML의 복제 시점 서식을 보존합니다. JavaScript 동작, SVG 개체, 외부 자산 또는 지원하지 않는 변환을 포함한 구성은 지원하지 않습니다. 지원하지 않는 개체가 포함되면 선택 묶음 전체의 명령을 거절합니다. 자세한 조작은 [사용 안내](USER_GUIDE.md)를 참고하세요.

HTML ZIP에는 저장 상태가 적용됩니다. PDF와 외형 보존 PPTX는 정지 화면이며, 편집형 PPTX는 지원 글·이미지만 분리합니다. CSS·3D·복잡한 장식은 배경으로 남고 글꼴·줄바꿈·회전 개체 배치가 달라질 수 있습니다. 실제 PowerPoint 앱에서 별도 확인하세요.

## 적용 전 확인과 백업

1. 실제 코드 경로, 현재 브랜치·커밋·자체 수정, 실행 방식, 환경 파일, `DATA_DIR`와 데이터 마운트를 확인합니다. 아래 경로는 설명용 자리표시자입니다.
2. 앱의 쓰기를 중단하거나 해당 앱 프로세스만 정지한 일관된 시점에 코드·환경 설정·`DATA_DIR` 전체를 함께 백업합니다. 자산, 메타데이터, 모든 revision, `_auth.json`이 모두 필요합니다.
3. 백업을 운영 경로와 분리해 보관하고 복원 가능한지 확인합니다. 운영 환경 파일·인증정보·발표 자료는 GitHub나 공개 이미지에 포함하지 않습니다.
4. 스테이징 코드와 데이터 복사본을 별도 준비합니다. 운영 `DATA_DIR`에 두 앱 프로세스를 동시에 연결하지 않습니다.

```bash
# 실제 운영 코드 체크아웃에서 읽기 확인
APP_DIR=/path/to/current/web-slides-studio
cd "$APP_DIR"
git status --short --branch
git rev-parse HEAD
```

Node 서비스명·Compose 파일명·데이터 경로를 이 문서의 예제로 추측해 교체하지 마세요. 현재 운영 구성과 자체 변경은 업데이트 전에 별도로 보존합니다.

## 스테이징 소스 업데이트와 자동 검증

깨끗한 스테이징 체크아웃의 `main`에서 업데이트합니다. 신규 스테이징은 공개 저장소를 복제하고, 기존 스테이징은 다음 명령 전에 현재 브랜치와 로컬 변경부터 확인하세요.

```bash
STAGING_DIR=/path/to/staging/web-slides-studio

# 신규 체크아웃이 필요한 경우에만 실행
git clone https://github.com/no1fc/web-slides-studio.git "$STAGING_DIR"

cd "$STAGING_DIR"
git status --short --branch
git switch main
git pull --ff-only origin main
git rev-parse HEAD
npm ci --ignore-scripts

# 실제 설치된 Chrome/Chromium 실행 파일을 지정
export CHROME_PATH=/usr/bin/chromium
test -x "$CHROME_PATH"
node --version
"$CHROME_PATH" --version
npm test
git diff --check
```

`git pull --ff-only`가 실패하면 서버 자체 커밋이나 로컬 변경과 새 소스의 차이를 확인하세요. 별도 작업 브랜치에서 충돌을 병합하고 같은 테스트를 다시 수행합니다. 강제 초기화나 파일 전체 덮어쓰기로 자체 변경을 버리지 않습니다. 기존 배포 파일과 운영 설정을 저장소 예제로 대체하지 않습니다.

Node.js 22를 권장하며 지원 범위는 Node.js 20 이상입니다. Chromium과 한글 글꼴이 필요합니다. CSS의 `@scope` 지원과 실제 출력 외형도 확인하세요. 기존 Dockerfile은 Chromium과 Noto CJK 글꼴을 포함하지만, 호스트나 자체 이미지는 별도로 준비해야 합니다.

검증한 Git 커밋과 Node·Chromium 버전, 테스트 결과를 배포 기록에 남깁니다. `npm test`는 자체 임시 자료를 사용합니다. 현재 운영 데이터에 대한 검증은 별도 스테이징 복사본에서 진행하세요.

## 스테이징 실행과 수동 확인

운영 데이터의 복사본 또는 새로운 비공개 디렉터리를 사용합니다. 아래 예시는 서버 loopback에만 바인딩합니다.

```bash
STAGING_DATA=/path/to/private/studio-staging-data
HOST=127.0.0.1 \
PORT=14310 CONTENT_PORT=14311 \
APP_ORIGIN=http://127.0.0.1:14310 \
CONTENT_ORIGIN=http://127.0.0.1:14311 \
DATA_DIR="$STAGING_DATA" \
CHROME_PATH="$CHROME_PATH" \
node src/server.js
```

원격 서버는 두 포트를 로컬로 전달해 확인합니다. 복사한 `_auth.json`이 있으면 해당 시점의 암호가 적용됩니다. 운영 공개 시에는 기존의 서로 다른 HTTPS 관리·콘텐츠 origin과 인증·렌더러 격리 구성을 유지합니다. 환경변수 세부 설명은 [운영 안내](OPERATIONS.md)를 참고하세요.

| 확인 항목 | 합격 기준 |
| --- | --- |
| 기존 자료·코드·마스터 | 이전 자료를 열고 코드·JSON·마스터 수정, 저장·새로고침·버전 복원이 동작 |
| 다중 선택·취소 | 수정키 클릭·영역 선택 후 여러 개체 이동, 한 번 Undo, Escape 취소 시 전체 원복 |
| 배율·정밀 조작 | 50·100·200%에서 문서 좌표 이동이 일치하고, 크기·회전·비율 유지가 동작 |

## 운영 반영

스테이징에서 검증한 커밋 또는 자체 변경을 병합해 검증한 커밋을 배포합니다. 운영 체크아웃도 변경사항이 없는 `main`이고 원격 이력으로 fast-forward할 수 있다면 `git pull --ff-only origin main`을 사용합니다. 갱신 후 SHA가 검증한 커밋과 같은지 확인하세요. 그사이 원격에 다른 커밋이 추가되었다면 해당 변경까지 검증한 뒤 반영합니다.

Node 직접 실행·서비스 관리 방식이면 기존 환경 파일과 데이터 경로를 유지하고 필요한 의존성을 설치한 뒤 실제 앱 서비스만 재시작합니다. Compose 방식이면 현재 사용하는 운영 Compose 파일·프로젝트·서비스를 확인하고 해당 앱 이미지를 다시 빌드·교체합니다. 서비스명은 배포마다 다르므로 임의의 `systemctl` 또는 Compose 재시작 명령을 제시하지 않습니다.

`src`와 `public`의 변경을 함께 반영해야 합니다. 일부 JavaScript만 바꾸면 UI와 서버의 상태 계약이 맞지 않을 수 있습니다. 재시작 후 편집 페이지를 새로고침하고 재로그인합니다. `/health`, 기존 자료 열기, 새 변경 저장, 레이어·복제 유지, HTML/PDF/PPTX 출력을 확인합니다. 정상 확인 전에는 적용 전 백업을 유지하세요.

## 롤백과 상태 호환성

`schemaVersion`은 1을 유지하지만 새 상태에는 코드·마스터와 HTML 복제 개체, `z`·`locked`·`layerPosition` 등이 추가될 수 있습니다. 이전 validator는 이 필드를 해석하지 못하므로 **새 데이터를 둔 채 코드만 이전 버전으로 되돌리는 방식은 안전한 롤백이 아닙니다.**

문서 변경만 되돌리려면 새 코드의 Undo 또는 버전 복원을 사용합니다. 배포 전체를 되돌려야 하면 앱을 중지하고 최신 데이터도 별도로 보존한 다음, 적용 전 코드·환경 설정·전체 데이터 백업을 함께 복구합니다. 새 버전에서 작성한 변경은 이전 백업에 없으므로 보존 여부를 확인해야 합니다. 복원한 인증 파일에 따라 유효한 암호도 백업 시점으로 돌아갈 수 있습니다.

복구 대상 경로와 유지할 최신 변경을 확인하지 않은 자동 삭제·덮어쓰기 롤백은 수행하지 않습니다.

## 검증 기록

개발 검증 환경: Windows, Node.js 22.14.0, Chrome 156.0.8078.47.

통합 후 `npm test` 결과는 **89개 통과, 실패 0개**입니다. 복원·저장 경합, 복제 개체 글꼴 적용, 중앙이 아닌 회전 원점의 복제 위치, 잠긴 형제 개체가 있는 레이어 순서의 회귀 검증을 포함합니다. 1280×800과 1600×1050 화면에서 2단계 UI 스크린샷을 확인했으며 브라우저 page error는 없었습니다.

Linux 운영 서버의 실제 실행, 실제 PowerPoint 프로그램 렌더링, OS 한글 IME 전체 수동 검증은 이 Windows 자동 검증 결과에 포함되지 않습니다. 위 스테이징·운영 확인 절차에서 별도로 기록하세요.
